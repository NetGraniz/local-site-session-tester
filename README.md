# Local Site Visitor

## Готовые сборки

Portable EXE, NSIS installer и ZIP исходного проекта опубликованы на странице [GitHub Releases](https://github.com/NetGraniz/local-site-session-tester/releases/latest). Контрольные суммы SHA-256 и результаты проверок приведены в [CHECKS.md](CHECKS.md).

Полная актуальная версия требований находится в [техническом задании](docs/Техническое%20задание%20для%20Codex.txt).

Полностью локальное Windows-приложение для контролируемого открытия одного URL в нескольких параллельных изолированных браузерных сессиях. Каждая сессия использует собственный `BrowserContext` Playwright: cookies, `localStorage`, `sessionStorage` и кэш не разделяются и удаляются после закрытия контекста.

> Используйте программу только для сайтов, которыми вы владеете или на тестирование которых имеете явное разрешение. Большое число параллельных сессий создаёт нагрузку на сайт и компьютер.

## Возможности

- один процесс Chromium и от 1 до 50 независимых контекстов;
- постоянный пул из заданного количества рабочих слотов без накопления фоновых Promise;
- однократный, ограниченный или бесконечный циклический режим;
- фиксированная длительность цикла или случайная длительность в заданном диапазоне;
- безопасные случайные переходы, нажатия и прокрутки по пользовательскому белому списку;
- воспроизводимые последовательности действий через необязательный seed;
- новый `BrowserContext` и страница для каждого цикла без переиспользования cookies и хранилищ;
- фоновый или видимый режим браузера;
- настраиваемые длительность сессии, задержка запуска, тайм-аут и viewport;
- HTTP-код, время загрузки и ошибка для каждой сессии;
- ограниченная по времени ручная остановка с принудительным завершением зависшего Chromium;
- локальные журналы без cookies, данных форм и содержимого страниц;
- сохранение только последних безопасных настроек;
- автономные Windows x64 сборки: portable EXE и NSIS installer.

## Системные требования

- Windows 10 или Windows 11 x64;
- около 1 ГБ свободного места для исходного проекта, зависимостей и сборок;
- для запуска готового EXE Node.js не нужен;
- для работы с исходниками: Node.js 20 LTS или новее и npm;
- интернет нужен только при первой установке зависимостей. Само приложение не использует облачные API.

## Установка Node.js

1. Скачайте LTS-версию с [nodejs.org](https://nodejs.org/).
2. Запустите установщик и оставьте включённым добавление Node.js в `PATH`.
3. Откройте новое окно PowerShell и проверьте:

```powershell
node --version
npm --version
```

## Установка и запуск через BAT

Из корня проекта:

```bat
scripts\install.bat
scripts\start.bat
```

`install.bat` проверяет Node.js, выполняет `npm install`, устанавливает Chromium Playwright внутрь проекта и дополнительно проверяет локальный Electron. Скрипт прекращает работу при любой ошибке.

## Запуск через PowerShell

```powershell
Set-Location "C:\путь\к\local-site-visitor"
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
npm install
npx playwright install chromium
npm start
```

## Параметры

| Параметр | Описание | Допустимые значения |
|---|---|---|
| URL сайта | Адрес тестируемой страницы | Только `http://` или `https://` |
| Сессий | Число независимых контекстов | 1–50, по умолчанию 5 |
| Режим длительности | Фиксированное время или новое случайное время для каждого цикла | По умолчанию фиксированное |
| Фиксированная длительность | Сколько держать загруженную страницу открытой | 10–86400 секунд, по умолчанию 15 |
| Диапазон длительности | Включительные минимум и максимум для случайного выбора каждого цикла | 10–86400 секунд, по умолчанию 15–60 |
| Задержка старта | Интервал между запусками сессий | 0–60000 мс, по умолчанию 300 |
| Тайм-аут загрузки | Максимальное время `page.goto()` | 1000–300000 мс, по умолчанию 30000 |
| Режим браузера | Фоновый или видимый Chromium | По умолчанию фоновый |
| Размер окна | Viewport каждой страницы | Ширина 320–7680, высота 240–4320; по умолчанию 1280 × 720 |
| Повторять завершённые сессии | Запускает новый цикл в том же рабочем слоте | По умолчанию выключено |
| Режим повторов | Без ограничений или заданное количество | По умолчанию без ограничений |
| Циклов на слот | Максимум полных заходов каждого worker-слота | 1–100000, по умолчанию 10 |
| Задержка перезапуска | Пауза после закрытия предыдущего контекста | 0–3600000 мс, по умолчанию 1000 |
| Останавливать слот после ошибки | Завершает только ошибочный слот | По умолчанию выключено |
| Случайные действия | Выполняет безопасную последовательность после загрузки страницы | По умолчанию выключено |
| Количество действий | Случайное число действий на цикл | 1–100, по умолчанию 1–5 |
| Задержка действий | Прерываемая пауза между действиями | 100–60000 мс, по умолчанию 800–2500 |
| Глубина переходов | Максимальное число последовательных переходов вперёд | 0–20, по умолчанию 3 |
| Seed | Повторяет выбор действий при одинаковом состоянии сайта | 0–4294967295 или автоматически |
| Автопоиск элементов | Экспериментально расширяет белый список после проверок | По умолчанию выключен |
| Копировать адрес сервера | Нажимает отдельную разрешённую кнопку до или после случайных действий | По умолчанию выключено |

Настройки проверяются и в интерфейсе, и повторно в main-процессе. Пока тест активен, поля и повторный запуск заблокированы.

## Циклический режим

Каждый рабочий слот выполняется последовательно: выбирает длительность цикла, создаёт контекст и страницу, загружает URL, выдерживает выбранное время, закрывает страницу и контекст, ждёт задержку перезапуска и только затем начинает следующий цикл. В режиме диапазона новое целое число секунд выбирается включительно между указанными минимумом и максимумом. Выбранное значение видно в таблице и журнале. Идентификаторы имеют вид `slot-3-cycle-17`.

При режиме **«Без ограничений»** тест продолжается до ручной остановки. При ограниченном режиме каждый слот самостоятельно завершится после указанного числа циклов. Ошибка отдельного цикла по умолчанию учитывается в статистике и не останавливает остальные циклы; тумблер **«Останавливать слот после ошибки»** меняет это поведение только для конкретного слота.

Кнопка остановки отменяет задержки через `AbortController`, запрещает создание новых контекстов, закрывает активные страницы и контексты и дожидается worker-задач. Мягкое закрытие каждого ресурса ограничено по времени; отдельный `BrowserServer` Playwright позволяет принудительно завершить Chromium, если страница, контекст или соединение зависли.

## Безопасные случайные действия

Основной режим взаимодействует только с элементами, подходящими под **«Разрешённые селекторы»**. Запрещённые селекторы и опасный текст всегда имеют приоритет. Встроенные критические ограничения дополнительно блокируют submit-кнопки, элементы форм, загрузки файлов, ссылки `target="_blank"`/`download` и опасные административные или платёжные действия.

Перед каждым кликом приложение повторно проверяет видимость, доступность, origin и текст элемента. Переходы разрешены только внутри исходного `origin`; `mailto:`, `tel:`, `javascript:`, `data:` и `file:` не используются. Навигационные запросы на внешний origin, дополнительные окна и загрузки файлов блокируются также на уровне `BrowserContext`.

Экспериментальный автопоиск выключен по умолчанию. Он рассматривает только:

```text
nav a[href]
main a[href]
[role="navigation"] a[href]
button:not([type="submit"])
[role="button"]
```

Пустой seed генерируется отдельно для каждого цикла и записывается в журнал. Фиксированный seed воспроизводит выбор количества, типа, элемента, задержки и параметров прокрутки при одинаковом состоянии и порядке DOM. Изменения сайта или сетевых задержек могут изменить фактический результат клика.

Случайные действия входят в выбранную длительность цикла: после них приложение ждёт только оставшееся время. Все поиски и задержки учитывают `AbortSignal`, поэтому после остановки новые действия не запускаются.

## Статусы

- **Ожидание** — сессия запланирована;
- **Запуск** — создаётся изолированный контекст;
- **Загрузка** — выполняется переход по URL;
- **Активно** — DOM загружен, идёт заданная выдержка;
- **Завершено** — сессия успешно закрыта;
- **Ошибка** — ошибка сети, тайм-аут или ответ HTTP 4xx/5xx;
- **Остановлено** — сессия отменена пользователем.

HTTP 4xx и 5xx фиксируются как обычный ответ сервера: код остаётся в таблице, а пояснение выводится рядом и в журнале.

## Журналы и настройки

Данные хранятся в стандартной папке Electron:

```text
%APPDATA%\Local Site Visitor\
├─ settings.json
└─ logs\
   └─ session-YYYY-MM-DD-HH-mm-ss.log
```

Точный путь можно открыть кнопкой **«Открыть папку журналов»**. В журнал не записываются cookies, содержимое хранилищ, пароли, формы и HTML страниц. При повреждении `settings.json` используются значения по умолчанию.

## Создание EXE

Самый простой способ:

```bat
scripts\build.bat
```

Или отдельно:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
npm run pack:win
npm run dist:win
```

Артефакты появляются в `dist\`:

- `Local Site Visitor-1.3.0-x64-portable.exe`;
- `Local Site Visitor-1.3.0-x64-setup.exe`.

Chromium Playwright включён в сборку, поэтому на целевом компьютере не требуется отдельно выполнять `playwright install`.

## Проверки

```powershell
npm run check
npx electron --version
npx playwright --version
npm run test:scheduler
npm run test:browser
npm run test:repeat-browser
npm run test:runtime
npm run test:actions
npm run test:ui
npm run smoke
npm run smoke:cycles
npm run smoke:stop
npm run smoke:actions
```

`test:scheduler` проверяет планировщик, `test:runtime` — случайную длительность и тайм-аут зависшего Promise, а `test:actions` — seed, белый и чёрный списки, внутренний origin, опасные формы, прокрутку, копирование и отмену. `test:browser` проверяет изоляцию контекстов, `test:repeat-browser` — девять повторных циклов. Smoke-тесты проверяют окно, циклы, остановку 12 зависших загрузок и полную интеграцию случайных действий через Electron.

## Решение типовых ошибок

### `"electron" не является внутренней или внешней командой`

Команда `electron` не должна запускаться глобально. Используйте `npm start`, `npx electron --version` или `scripts\start.bat`. Если локальная установка повреждена:

```powershell
Remove-Item -Recurse -Force node_modules
Remove-Item package-lock.json -Force
npm cache verify
npm install
npx electron --version
npm start
```

### Chromium отсутствует

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
npx playwright install chromium
```

### DNS, отказ соединения, SSL или тайм-аут

Проверьте URL в обычном браузере, настройки прокси/антивируса и доступность DNS. Увеличьте тайм-аут. Текст исходной ошибки Playwright будет в таблице и локальном журнале.

### Сборка завершается с ошибкой

Закройте ранее запущенный EXE, проверьте свободное место и повторите `scripts\install.bat`, затем `scripts\build.bat`. Антивирус может временно блокировать упаковку неподписанного EXE.

## Ограничения по нагрузке

Лимит интерфейса — 50 сессий, но безопасное число зависит от процессора, памяти и тестируемого сайта. Начинайте с 3–5 сессий и увеличивайте постепенно. Видимый режим требует больше ресурсов. Программа не является инструментом стресс-тестирования или обхода защит.

## Безопасность

Окно Electron работает с `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Renderer видит только ограниченный IPC API через `preload.js`; удалённый HTML в окно приложения не загружается. URL проверяется в main-процессе, а данные страниц не сохраняются. В журнал попадают только сокращённый текст элемента, селектор, URL с редактированием чувствительных параметров, результат и длительность действия; значения полей, формы, cookies и токены не читаются.
