# Local Site Visitor

## Готовые сборки

Portable EXE, NSIS installer и ZIP исходного проекта опубликованы на странице [GitHub Releases](https://github.com/NetGraniz/local-site-session-tester/releases/latest). Контрольные суммы SHA-256 и результаты проверок приведены в [CHECKS.md](CHECKS.md).

Полностью локальное Windows-приложение для контролируемого открытия одного URL в нескольких параллельных изолированных браузерных сессиях. Каждая сессия использует собственный `BrowserContext` Playwright: cookies, `localStorage`, `sessionStorage` и кэш не разделяются и удаляются после закрытия контекста.

> Используйте программу только для сайтов, которыми вы владеете или на тестирование которых имеете явное разрешение. Большое число параллельных сессий создаёт нагрузку на сайт и компьютер.

## Возможности

- один процесс Chromium и от 1 до 50 независимых контекстов;
- фоновый или видимый режим браузера;
- настраиваемые длительность сессии, задержка запуска, тайм-аут и viewport;
- HTTP-код, время загрузки и ошибка для каждой сессии;
- корректная ручная остановка и подтверждение выхода при активном тесте;
- локальные журналы без cookies, данных форм и содержимого страниц;
- сохранение только последних безопасных настроек;
- автономные Windows x64 сборки: portable EXE и NSIS installer.

## Системные требования

- Windows 10 или Windows 11 x64;
- около 1 ГБ свободного места для исходного проекта, зависимостей и сборок;
- для запуска готового EXE Node.js не нужен;
- для работы с исходниками: Node.js 20 LTS или новее и npm;
- интернет нужен только при первой установке зависимостей. Само приложение не использует облачные API.

## Установка Node.js

1. Скачайте LTS-версию с [nodejs.org](https://nodejs.org/).
2. Запустите установщик и оставьте включённым добавление Node.js в `PATH`.
3. Откройте новое окно PowerShell и проверьте:

```powershell
node --version
npm --version
```

## Установка и запуск через BAT

Из корня проекта:

```bat
scripts\install.bat
scripts\start.bat
```

`install.bat` проверяет Node.js, выполняет `npm install`, устанавливает Chromium Playwright внутрь проекта и дополнительно проверяет локальный Electron. Скрипт прекращает работу при любой ошибке.

## Запуск через PowerShell

```powershell
Set-Location "C:\путь\к\local-site-visitor"
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
npm install
npx playwright install chromium
npm start
```

## Параметры

| Параметр | Описание | Допустимые значения |
|---|---|---|
| URL сайта | Адрес тестируемой страницы | Только `http://` или `https://` |
| Сессий | Число независимых контекстов | 1–50, по умолчанию 5 |
| Длительность | Сколько держать загруженную страницу открытой | 0–86400 секунд, по умолчанию 15 |
| Задержка старта | Интервал между запусками сессий | 0–60000 мс, по умолчанию 300 |
| Тайм-аут загрузки | Максимальное время `page.goto()` | 1000–300000 мс, по умолчанию 30000 |
| Режим браузера | Фоновый или видимый Chromium | По умолчанию фоновый |
| Размер окна | Viewport каждой страницы | Ширина 320–7680, высота 240–4320; по умолчанию 1280 × 720 |

Настройки проверяются и в интерфейсе, и повторно в main-процессе. Пока тест активен, поля и повторный запуск заблокированы.

## Статусы

- **Ожидание** — сессия запланирована;
- **Запуск** — создаётся изолированный контекст;
- **Загрузка** — выполняется переход по URL;
- **Активно** — DOM загружен, идёт заданная выдержка;
- **Завершено** — сессия успешно закрыта;
- **Ошибка** — ошибка сети, тайм-аут или ответ HTTP 4xx/5xx;
- **Остановлено** — сессия отменена пользователем.

HTTP 4xx и 5xx фиксируются как обычный ответ сервера: код остаётся в таблице, а пояснение выводится рядом и в журнале.

## Журналы и настройки

Данные хранятся в стандартной папке Electron:

```text
%APPDATA%\Local Site Visitor\
├─ settings.json
└─ logs\
   └─ session-YYYY-MM-DD-HH-mm-ss.log
```

Точный путь можно открыть кнопкой **«Открыть папку журналов»**. В журнал не записываются cookies, содержимое хранилищ, пароли, формы и HTML страниц. При повреждении `settings.json` используются значения по умолчанию.

## Создание EXE

Самый простой способ:

```bat
scripts\build.bat
```

Или отдельно:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
npm run pack:win
npm run dist:win
```

Артефакты появляются в `dist\`:

- `Local Site Visitor-1.0.0-x64-portable.exe`;
- `Local Site Visitor-1.0.0-x64-setup.exe`.

Chromium Playwright включён в сборку, поэтому на целевом компьютере не требуется отдельно выполнять `playwright install`.

## Проверки

```powershell
npm run check
npx electron --version
npx playwright --version
npm run test:browser
npm run smoke
```

`test:browser` запускает Chromium, открывает локальную страницу в двух контекстах и проверяет изоляцию cookies и `localStorage`. Smoke test загружает локальное окно Electron в скрытом режиме, печатает `SMOKE_TEST_OK` и завершает приложение.

## Решение типовых ошибок

### `"electron" не является внутренней или внешней командой`

Команда `electron` не должна запускаться глобально. Используйте `npm start`, `npx electron --version` или `scripts\start.bat`. Если локальная установка повреждена:

```powershell
Remove-Item -Recurse -Force node_modules
Remove-Item package-lock.json -Force
npm cache verify
npm install
npx electron --version
npm start
```

### Chromium отсутствует

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
npx playwright install chromium
```

### DNS, отказ соединения, SSL или тайм-аут

Проверьте URL в обычном браузере, настройки прокси/антивируса и доступность DNS. Увеличьте тайм-аут. Текст исходной ошибки Playwright будет в таблице и локальном журнале.

### Сборка завершается с ошибкой

Закройте ранее запущенный EXE, проверьте свободное место и повторите `scripts\install.bat`, затем `scripts\build.bat`. Антивирус может временно блокировать упаковку неподписанного EXE.

## Ограничения по нагрузке

Лимит интерфейса — 50 сессий, но безопасное число зависит от процессора, памяти и тестируемого сайта. Начинайте с 3–5 сессий и увеличивайте постепенно. Видимый режим требует больше ресурсов. Программа не является инструментом стресс-тестирования или обхода защит.

## Безопасность

Окно Electron работает с `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Renderer видит только ограниченный IPC API через `preload.js`; удалённый HTML в окно приложения не загружается. URL проверяется в main-процессе, а данные страниц не сохраняются.
