Техническое задание для Codex

Создай полностью локальное Windows-приложение с графическим интерфейсом для контролируемого тестирования собственного сайта через параллельные изолированные браузерные сессии.

Назначение

Программа должна открывать указанный URL в нескольких параллельных независимых браузерных сессиях. Каждая сессия должна иметь отдельные cookies, localStorage, sessionStorage и кэш, аналогично приватному окну.

Приложение предназначено только для тестирования сайтов, которыми пользователь владеет или на тестирование которых имеет разрешение.

Технологии

Используй:

Electron
Node.js
Playwright
HTML
CSS
Vanilla JavaScript

Не используй React, Vue, TypeScript, Docker, внешнюю базу данных, облачные API или удалённый сервер.

Приложение должно работать полностью локально на Windows 10 и Windows 11.

## Циклический перезапуск сессий

Добавь в интерфейс тумблер:

```text
Повторять завершённые сессии
```

Когда тумблер выключен, программа работает как раньше: создаёт указанное количество сессий, выполняет каждую один раз и завершает тест.

Когда тумблер включён, каждая завершённая сессия должна автоматически запускаться заново в новом изолированном `BrowserContext`.

Пример:

```text
Количество параллельных сессий: 5
Продолжительность: 20 секунд
Повторять завершённые сессии: включено
```

Программа должна постоянно поддерживать до пяти параллельных активных задач. Когда одна задача завершается, её слот освобождается, после чего создаётся новая сессия с новым контекстом.

### Требования к повторному запуску

Каждый новый цикл должен:

```text
создавать новый browser.newContext()
создавать новую страницу
не переиспользовать cookies
не переиспользовать localStorage и sessionStorage
закрывать предыдущий контекст перед повторным запуском
учитывать заданную задержку перед перезапуском
```

Не переиспользовать старую страницу или старый контекст.

Добавь параметр:

```text
Задержка перед повторным запуском, мс
```

Значение по умолчанию:

```text
1000 мс
```

### Ограничение повторов

Добавь выбор режима:

```text
Без ограничений
Заданное количество циклов
```

При выборе количества циклов показать числовое поле:

```text
Количество циклов на каждый слот
```

Допустимые значения:

```text
минимум: 1
максимум: 100000
```

Один цикл означает один полный заход: создание контекста, загрузку страницы, ожидание и закрытие контекста.

При режиме «Без ограничений» выполнение продолжается до нажатия кнопки «Остановить».

### Логика планировщика

Реализуй пул постоянных рабочих слотов:

```javascript
async function runWorkerSlot(slotId, options, abortSignal) {
  let cycle = 0;

  while (!abortSignal.aborted) {
    cycle += 1;

    await runIsolatedSession({
      slotId,
      cycle,
      options,
      abortSignal
    });

    if (!options.repeatEnabled) {
      break;
    }

    if (
      options.repeatMode === "limited" &&
      cycle >= options.maxCycles
    ) {
      break;
    }

    await abortableDelay(
      options.restartDelayMs,
      abortSignal
    );
  }
}
```

Это пример архитектуры, а не обязательный дословный код.

Не создавай бесконтрольное количество Promise. Должно существовать ровно столько worker-задач, сколько указано параллельных слотов.

### Остановка циклического режима

При нажатии «Остановить»:

```text
немедленно запретить запуск новых циклов
прервать задержки между циклами
закрыть активные страницы и контексты
дождаться завершения worker-задач
закрыть Chromium
перевести незавершённые циклы в статус «Остановлена»
```

Используй `AbortController` или эквивалентный механизм отмены.

После остановки ни один новый контекст не должен создаваться.

### Поведение при ошибках

По умолчанию ошибка отдельного цикла не должна останавливать весь тест. После записи ошибки задача может перейти к следующему циклу.

Добавь настройку:

```text
Останавливать слот после ошибки
```

Когда настройка выключена, слот повторяется после ошибки.

Когда включена, конкретный слот прекращает работу после первой ошибки, но остальные слоты продолжают работу.

Критическая ошибка запуска Chromium должна останавливать весь тест.

## Режим длительности цикла

Добавь выбор:

```text
Фиксированная длительность
Случайная длительность в диапазоне
```

В фиксированном режиме каждый цикл использует указанное значение. В режиме диапазона пользователь задаёт минимальную и максимальную длительность, а каждый новый цикл независимо выбирает случайное целое число секунд включительно между этими границами.

Для фиксированной длительности, минимума и максимума действует нижний порог 10 секунд. Максимум диапазона не может быть меньше минимума. Выбранная для конкретного цикла длительность должна отображаться в таблице сессий и записываться в журнал. Настройки сохраняются в `settings.json`:

```json
{
  "durationMode": "fixed",
  "durationSeconds": 15,
  "minDurationSeconds": 15,
  "maxDurationSeconds": 60
}
```

## Гарантированная остановка зависших сессий

Остановка не должна бесконечно ждать зависшие операции Playwright. Мягкое закрытие страницы, контекста и браузера необходимо ограничить по времени. Если закрытие не завершается, программа должна принудительно завершить принадлежащий текущему тесту процесс Chromium, освободить состояние запуска и вернуть интерфейс в остановленное состояние.

Ошибка или тайм-аут отдельной загрузки по-прежнему не считается критической ошибкой всего теста. После остановки не должны оставаться процессы Chromium, созданные программой, даже если одновременно выполнялось много загрузок с ошибкой.
